# incremental-bundler-go

面向工作区源码的模块打包引擎：把分散的源文件按依赖关系解析、转换并合成为可交付产物，
并用一份可持久化的内容寻址缓存让重复构建只重做真正变化的部分。整条链路在单进程内运行，
不依赖外部服务。

## 快速开始

```go
cfg := bundler.Config{
    Root:       "workspace/",                 // 工作区根目录（也可只用进程内 Source）
    Entries:    []string{"src/main.js"},      // 入口模块
    Transforms: []bundler.Transform{myStep},   // 转换流水线，按顺序执行
    Split:      bundler.SplitNone,            // 或 SplitPerEntry 按入口拆分
    CacheDir:   ".bundler-cache",             // 持久化缓存目录（空 = 仅内存）
    OutDir:     "dist/",                      // 产物输出目录（空 = 不落盘）
    Workers:    8,                            // 转换并发度
}
res, err := bundler.New(cfg).Build(ctx, sources)
```

输入可以全部来自磁盘（`Root` + `Entries`），也可以进程内提供
（`Source{Path, Content, HasContent: true}`），进程内内容优先于磁盘。

## 依赖解析规则

- 从入口出发按广度优先遍历，源码中的 `import ... from "x"`、`import "x"` 与
  `require("x")` 都会被识别为依赖。
- 引用串解析：`./`、`../` 相对引用基于引用方所在目录，其余基于工作区根；
  依次尝试 `原样`、`追加 .js`、`追加 /index.js`。
- **重复模块**：同一模块被多处引用时只保留一个节点，天然去重。
- **缺失依赖**：记录为 `DepMissing` 边并汇总到 `Graph.Missing`，不中断其他模块的解析。
- **循环依赖**：用迭代式 Tarjan SCC 检测（不会因深图耗尽栈）。每个环确定化记录为
  `Cycle{Members, Entry}`：`Members` 按字典序排序，`Entry` 为其中最小者。合成时环成员
  在拓扑序中连续出现（Entry 在前、各一次），并在产物中带
  `(cyclic dependency group member)` 标注——环不会被静默丢弃，也不会无限递归。
- 拓扑序在环压缩后的 DAG 上用字典序 Kahn 算法计算，同一输入结果确定可复现。

## 转换流水线

`Transforms` 按固定顺序对每个模块依次执行。任一步骤失败即中止该模块，返回
`*TransformError`（含 `Module` 与 `Step` 字段，可定位）；半成品内容不写入缓存也不进入
产物，其他模块的转换与缓存提交不受影响。构建结束时聚合返回所有模块错误。

## 缓存键语义

每个模块的缓存键（`Module.OutHash`）由以下内容派生：

1. 模块自身源内容的 SHA-256；
2. 每条依赖边的 `(引用串, 解析状态, 解析结果, 依赖的缓存键)`——因此**任何上游内容或
   解析关系的变化都会沿依赖边传导，使全部下游失效**；依赖从缺失变为存在（或反之）
   同样改变键；
3. 转换流水线指纹（各步骤名），流水线配置变化会使全部缓存失效；
4. 环成员共享环键：任一环成员内容或环的外部依赖变化，整环一起失效。

键只依赖内容而非时间戳，因此**全量构建与增量构建在同一输入下产出逐字节一致的产物**。

## 缓存持久化与一致性

缓存目录布局：

```
<CacheDir>/VERSION         格式版本号
<CacheDir>/entries/<key>   缓存项，内容为 "<sha256(payload)>\n<payload>"
```

- **版本兼容**：`VERSION` 与当前格式版本不符（或损坏）时，自动清空并重建为空缓存，
  安全回退全量重建，不崩溃、无需人工清理。
- **损坏识别**：每个缓存项自带校验哈希，读取时校验失败按未命中处理并清除该项。
- **原子提交**：所有写入（缓存项、VERSION、产物、`.manifest`）都先写唯一临时文件再
  `rename` 提交，任何时刻读到的都是完整内容；多进程共享同一缓存目录是安全的。
- **取消与恢复**：构建被取消或中途失败时，已提交的缓存项保持完整且可被下次构建复用；
  产物不落盘，重新构建从最近一致位置继续，不重复应用也不跳过变化。
- **产物一致性**：`OutDir` 中的产物原子落盘，`.manifest` 记录本轮产物清单，上一轮
  产物中不再产出的文件（入口删除/改名）会被自动清理，半成品产物不会对外可见。

## 产物合成

- `SplitNone`：全部模块按拓扑序合成单一产物 `bundle.js`。
- `SplitPerEntry`：每个入口一个产物 `<入口路径>.bundle.js`（`/` 替换为 `_`），
  内容为该入口的传递闭包。同一输入同一配置下，拆分结果与命名确定且可复现。

## 源码变更的反映

模块的新增、删除与改名都会改变图结构与相关模块的缓存键：删除依赖后旧内容不再进入
产物（图按当前输入重建，无残留状态），改名等价于删除 + 新增。

## 测试

```sh
go test ./... -race
```

覆盖：循环/自环/缺失/重复依赖、超深依赖链、增量失效传导、全量与增量字节一致、
缓存版本不兼容与缓存项损坏回退、并发构建共享缓存（含多进程风格）、取消后恢复、
产物原子落盘与旧产物清理、按入口拆分的确定性。
